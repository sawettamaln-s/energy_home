# Energy Home

แอปมือถือ (Flutter) สำหรับติดตามค่าไฟฟ้าและค่าน้ำประปาของบ้านแบบรายรอบบิล
บันทึกเลขมิเตอร์ระหว่างเดือน คำนวณค่าใช้จ่ายตามอัตราจริงของ กฟน./กฟภ./กปน./กปภ.
คาดการณ์ยอดก่อนบิลจริงจะมา และวิเคราะห์การใช้งานเทียบกับเดือนก่อน ปีก่อน และฤดูกาล

## การใช้งาน

**สมัครและตั้งค่าเริ่มต้น**
1. สมัครด้วยอีเมล/รหัสผ่าน หรือบัญชี Google
2. เลือกพื้นที่ (กรุงเทพและปริมณฑล / ส่วนภูมิภาค) — ใช้ร่วมกันทั้งไฟฟ้าและน้ำ
3. เลือกประเภทมิเตอร์ไฟฟ้า
   - มิเตอร์ปกติ: อัตราประเภท 1.2 (กฟภ. เรียก 1.1.2) ใช้เกิน 150 หน่วย/เดือน
   - มิเตอร์ TOU: อัตรา TOU บ้านอยู่อาศัยแรงดันต่ำ (กฟน. ต่ำกว่า 12 kV / กฟภ. ต่ำกว่า 22 kV)

**ก่อนเริ่มคำนวณ** หน้าหลักจะแสดงเช็คลิสต์ 3 ขั้นตอน (และมีคู่มือ popup ตอนเข้าครั้งแรก)
1. **วันตัดรอบบิล** — วันที่จดเลขมิเตอร์บนใบแจ้งหนี้ ไฟฟ้าและน้ำใช้วันเดียวกัน
   (ถ้าสองใบมาไม่ตรงกัน แนะนำให้ใช้ใบที่มาทีหลัง)
2. **เลขมิเตอร์จากใบแจ้งหนี้** — เลขมิเตอร์และยอดเงินจากใบแจ้งหนี้ล่าสุด
   ใช้เป็นจุดเริ่มคำนวณรอบบิล (กรอกใหม่ทุกครั้งที่ได้ใบแจ้งหนี้ใบใหม่)
3. **เพิ่มบิลเดือนเก่าเข้าระบบ** (ไม่บังคับ) — ย้อนหลังได้ 5 เดือน รวมกับบิลล่าสุด
   เป็น 6 เดือน ให้หน้าวิเคราะห์มีข้อมูลเปรียบเทียบตั้งแต่วันแรก

## ฟีเจอร์

- **หน้าหลัก** — ความคืบหน้าของรอบบิล, ค่าไฟ/ค่าน้ำที่ใช้ไปแล้ว, ยอดคาดการณ์สิ้นรอบ
  และยอดสรุปรวมรายจ่ายประจำ
- **บันทึกมิเตอร์ระหว่างเดือน** — คำนวณหน่วยและค่าใช้จ่ายสดขณะพิมพ์ เลขที่กรอกต้องไม่
  น้อยกว่าเลขต้นรอบและค่าที่บันทึกล่าสุดของรอบ (TOU เช็คแยก On-Peak/Off-Peak)
  ถ้าไม่ผ่าน ระบบจะบอกสาเหตุพร้อมปุ่มไปแก้ไข
- **วิเคราะห์** — เทียบเดือนก่อน / ปีก่อน / ค่าเฉลี่ย 6 เดือน, กราฟเทรนด์ค่าใช้จ่ายและหน่วย
  (แยก On-Peak/Off-Peak สำหรับ TOU), คาดการณ์ยอดบิลรอบนี้และรอบถัดไป และข้อสังเกตอัตโนมัติ
- **รายจ่ายประจำ** — ค่าใช้จ่ายคงที่รายเดือน (ค่าส่วนกลาง อินเทอร์เน็ต ฯลฯ) กำหนดช่วง
  เดือนที่มีผลได้ รวมเข้ายอดสรุปของแต่ละรอบ
- **อุปกรณ์** — ประมาณการไฟที่เครื่องใช้ไฟฟ้าแต่ละชิ้นใช้ต่อวัน/เดือน/ปี
  และสัดส่วนในหน้าวิเคราะห์ ว่าค่าไฟส่วนใหญ่มาจากเครื่องไหน (ใช้อัตราเฉลี่ย 4.5 บาท/หน่วย)
- **แจ้งเตือน** — เปิด/ปิดแยกประเภทได้ที่หน้าตั้งค่า
  - ถึงวันตัดรอบบิล (09:00) ให้บันทึกเลขมิเตอร์จากใบแจ้งหนี้ใหม่
  - ไม่ได้บันทึกมิเตอร์เกิน 5 วัน และรอบบิลที่ไม่มีข้อมูลเลย
  - ค่าใช้จ่ายรอบนี้สูงกว่าเดือนก่อน 30% ขึ้นไป / คาดการณ์สิ้นรอบสูงกว่า 15% ขึ้นไป
  - สรุปยอดเมื่อปิดรอบบิล

## การคาดการณ์

- **ยอดสิ้นรอบบิล** — อัตราเฉลี่ยต่อวัน = ยอดสะสม ณ วันที่บันทึกล่าสุด ÷ จำนวนวันตั้งแต่
  ต้นรอบ แล้วคูณจำนวนวันที่เหลือ (ถูกต้องไม่ว่าจะบันทึกทุกวันหรือเว้นหลายวัน)
- **เดือนถัดไป** — ค่าเฉลี่ย 3 เดือนล่าสุดหลังหักฤดูกาล × ตัวคูณฤดูกาลของเดือนเป้าหมาย
  แยกตามพื้นที่ ถ้ายังไม่รู้พื้นที่/ประเภทมิเตอร์จะใช้เส้นแนวโน้ม (linear regression) แทน
- **ตัวคูณฤดูกาล** สร้างจากสถิติการใช้จริงรายเดือนของภาคที่อยู่อาศัย (ข้อมูลเปิดของรัฐ):
  - ไฟฟ้า: สนพ. (EPPO) การใช้ไฟฟ้าในพื้นที่ [กฟน.](https://catalog.eppo.go.th/dataset/dataset_11_35)
    / [กฟภ.](https://gdcatalog.go.th/en/dataset/gdpublish-dataset-11-361) ตามสาขา
  - น้ำ: กปน. (MWA) [สถิติการใช้น้ำประปา](https://gdcatalog.go.th/dataset/gdpublish-cus-consumption)
    กลุ่มที่อยู่อาศัย (กปภ. ไม่เปิดเผยข้อมูลแยกประเภทผู้ใช้ จึงใช้รูปแบบของ กปน. แทน)
  - มิเตอร์ TOU ใช้รูปแบบเดียวกับมิเตอร์ปกติของภาคเดียวกัน (สถิติไม่ได้แยกประเภทมิเตอร์)
- **ความแม่นยำ** (ทายทีละเดือนในช่วง ม.ค. 2023 เป็นต้นไป จากกราฟที่สร้างด้วยข้อมูล
  2016–2022, วัดด้วย MAPE แปลผลตาม Lewis 1982: ต่ำกว่า 10% = แม่นยำสูง)

  | ชุดข้อมูล | ฤดูกาล (วิธีหลัก) | เส้นแนวโน้ม | ใช้ค่าเดือนก่อน |
  |---|---|---|---|
  | ไฟฟ้า กทม. | 4.9% | 16.7% | 7.8% |
  | ไฟฟ้า ภูมิภาค | 5.0% | 18.5% | 8.3% |
  | น้ำ กทม. | 1.4% | 4.0% | 4.1% |

  ตัวเลขนี้วัดกับยอดรวมทั้งภาค ซึ่งเรียบกว่าบ้านหลังเดียว ความแม่นยำต่อบ้านวัดได้ด้วย
  `tool/backtest_forecast.dart` กับบิลจริงของผู้ใช้

## สถาปัตยกรรม

```
lib/
├── models/       ข้อมูล (BillModel, UserModel, ElectricityLogModel, ...)
├── screens/      หน้าจอแบ่งตามฟีเจอร์ (auth, dashboard, analysis, appliance, settings)
├── services/     Firestore, การวิเคราะห์, การแจ้งเตือน, Google Sign-In
├── styles/       สี (AppColors), ขนาดตัวอักษร, ระยะห่าง, การปรับขนาดตามจอ
├── utils/        ตรรกะล้วนไม่พึ่ง Firebase/widget (อัตราค่าไฟ-น้ำ, รอบบิล, คาดการณ์)
└── widgets/      widget ที่ใช้ร่วมกันหลายหน้าจอ
```

- ข้อมูลผู้ใช้อยู่ใน Firestore ใต้ `users/{uid}` (บิล, บันทึกมิเตอร์ไฟ/น้ำ,
  เลขมิเตอร์ต้นรอบ, อุปกรณ์, รายจ่ายประจำ) อ่าน/เขียนผ่าน `FirestoreService` เท่านั้น
  ค่า Ft อยู่ที่ `app_config/electricity_rates` (แก้ได้จาก Firebase Console เท่านั้น)
- `EnergyForecaster` (`lib/utils/forecaster.dart`) เป็นแหล่งความจริงเดียวของขอบเขต
  รอบบิลและการคาดการณ์ — บิลตั้งชื่อด้วยเดือนที่ปิดรอบ วันตัดรอบเป็นวันแรกของรอบใหม่
- ระบบปิดบิลรอบที่จบแล้วให้อัตโนมัติจากบันทึกมิเตอร์ (`compileBill`) ตอนเปิดหน้าหลัก
  โดยประมาณยอดจากบันทึกครั้งสุดท้ายไปถึงวันตัดรอบ เมื่อตั้งเลขมิเตอร์จากใบแจ้งหนี้
  หรือแก้บิลในหน้าเพิ่มบิลเดือนเก่า ยอดจริงจะแทนที่ยอดประมาณ
- แท็บหลักทั้ง 4 อยู่ใน `IndexedStack` จึงใช้ `DataRefreshBus` แจ้งให้หน้าอื่นโหลดใหม่
  เมื่อข้อมูลเปลี่ยน
- ประวัติแจ้งเตือนและการตั้งค่าแจ้งเตือนเก็บในเครื่อง (SharedPreferences) แยกตามบัญชี

## เริ่มต้นพัฒนา

ต้องมี [Flutter SDK](https://docs.flutter.dev/get-started/install) และโปรเจกต์ Firebase
ของตัวเอง — `lib/firebase_options.dart` และ `android/app/google-services.json` ไม่อยู่
ใน repo ให้รัน `flutterfire configure` หรือคัดลอก `lib/firebase_options.sample.dart`
เป็น `lib/firebase_options.dart` แล้วใส่ค่าจริง

```bash
flutter pub get
flutter run
```

## เทสและตรวจโค้ด

เทสใน `test/` ใช้ `fake_cloud_firestore` และ `firebase_auth_mocks` แทน Firebase จริง
ครอบคลุม: การปิดบิล, การคาดการณ์สิ้นรอบ, migration บิล TOU, กติกาฟอร์มเลขต้นรอบ,
หน้าบันทึกมิเตอร์, หน้าเลขมิเตอร์จากใบแจ้งหนี้, เงื่อนไขแจ้งเตือน, auth routing และ widget กลาง

```bash
flutter analyze
flutter test
flutter test test/record_meter_screen_test.dart   # รันไฟล์เดียว
```

GitHub Actions รัน `flutter analyze` และ `flutter test` ทุกครั้งที่ push/PR เข้า `master`

## เครื่องมือ (`tool/`)

สคริปต์แยกจากแอป รันด้วย `dart run` หรือ `python`:

| เครื่องมือ | ใช้ทำอะไร |
|---|---|
| `seasonal_curves/build_seasonal_curves.py` | สร้าง `lib/utils/seasonal_curves.dart` จากข้อมูลจริง (`--fetch` ดาวน์โหลดใหม่) |
| `seasonal_curves/backtest_forecast_methods.py` | วัด MAPE ของวิธีคาดการณ์กับข้อมูลชุดเดียวกัน |
| `backtest_forecast.dart` | วัดความแม่นยำการคาดการณ์กับบิลจริงของบัญชีหนึ่ง |
| `demo_data/generate_demo_account.dart` | เติมข้อมูลเดโมให้บัญชีที่สมัครแล้ว ตาม 4 เคส (กทม./ตจว. × ปกติ/TOU) |
| `migrate_tou_bills.dart` | ซ่อมบิล TOU ที่ระบบปิดให้แต่หน่วย On/Off-Peak เป็น 0 (ดู `tool/README_migrate_tou_bills.md`) |
| `list_bills.dart` | ดูบิลทั้งหมดของบัญชีหนึ่ง (อ่านอย่างเดียว) |

สคริปต์ที่เขียนข้อมูลจะเป็น dry-run เสมอจนกว่าจะใส่ `--apply`
